# Reviewing: pull request

You are the lead, and the whole sequence runs in one turn. The kernel finds the clone by the repository name in the URL: the project root, or a nested repository under it (`src/Orders` in an umbrella); `--repo <path>` names it outright. No clone found: it fails with a clear line, and you tell the user to clone first.

1. Run `picket pullrequest prepare <url> --human` (the JSON form goes to the reviewer; keep the `repo_root` it names). It fetches `refs/pull/<id>/merge`, computes base and head, the review summary over that range with its `checklists`, and the PR's title and description (Azure DevOps: a PAT in `AZDO_PAT`, set once with `setx AZDO_PAT <token>` or in the `env` block of the untracked `.claude/settings.local.json`, never in a tracked file; GitHub: the `gh` CLI). A missing PAT is reported, not fatal: the review runs code-only. Any other error: print it and stop.
2. Spawn the reviewer once (type `picket:reviewer`), named `reviewer`, with `scope: pr` and `pr: <the JSON from step 1, verbatim>`. Its verdict routes nowhere; the hook saves the block to `.picket/state/pr-<id>.review.md`.
3. Print the reviewer's block verbatim, then one options line: `[p] post to the PR   [d] done`. Nothing is written to the PR before `p`. When the block says `Alignment: N/A (no description)`, add one line under it: the PR carried no intent to check the diff against, so half the review is missing; a two-line description in the PR template restores it.
4. On `p`: run `picket pullrequest post <url> --file .picket/state/pr-<id>.review.md --dry-run --human`, adding the same `--repo <path>` when prepare needed it. The dry run prints the code at head under each finding's `path:line`. A code line that does not match its finding would put the thread on the wrong code: name each such finding to the user. Then ask once more with `[y] post   [n] keep local`; on `y`, run the same command without `--dry-run`. Posting is Azure DevOps only; on GitHub, tell the user to use `gh pr review`.
