# Command reference

Generated by `npm run docs` from `src/lib/verbs.mts` and each verb's `usage`; edit the source, not this page.

Usage: `picket <verb> [args] [--pretty | --human]`. Each verb prints JSON or text, and the flags below switch it. `picket --version` prints the installed version.

## Shared flags

| Flag | Does |
|---|---|
| `--root <path>` | run against the project at that path instead of the current one |
| `--human` | print text from a verb that prints JSON |
| `--json` | print JSON from a verb that prints text |
| `--pretty` | indent the JSON |
| `picket help <verb>` | print a verb's usage and summary; `picket help` prints every verb |

## Exit codes

| Code | Outcome | Means |
|---|---|---|
| 0 | done | the verb did its work |
| 1 | usage | the arguments are wrong or the verb is unknown |
| 1 | crash | an unexpected error |
| 2 | failed | the verb ran and reports a failure, such as a red check |
| 2 | refused | the verb refused the request and prints `{ "ok": false, "error": ... }` |

## picket admit

Choose the lane for a change request.

```sh
picket admit --text "<request>" | admit --request <file|-> [--touched <p1,p2>]
```

## picket check

Run the project's test and lint commands and log them.

```sh
picket check [--steps test,lint,build] [--only "<command>"] [--timeout <s>]
```

## picket close

Mark a work item done and commit what it owns.

```sh
picket close <id> [--message "<message>"] [--touched <p1,p2>]
```

## picket comment

Record the user's approval of one code comment.

Only the lead runs it; the Bash guard denies it to agents.

```sh
picket comment <id> --path <p> --text "<comment>"
```

## picket cost

Sum the ledger: turns, spend, cache, stops, bounces, escalations.

```sh
picket cost [--session <id>] [--work <id>]
```

## picket drive

Start the app or run a command, exercise it, stop it and log the evidence.

```sh
picket drive --run "<command>" | drive [--start "<command>"] --hit "<METHOD /path [json]>"... [--env NAME=VALUE]... [--port <n>] [--wait <path>] [--timeout <s>] [--keep-changes] [--work <id>] [--phase <n>]
```

## picket extension

Manage the project's extensions.

### picket extension add

Write a new extension's manifest and enable it.

```sh
picket extension add <name>
```

### picket extension list

List the enabled, refused and unlisted extensions.

```sh
picket extension list
```

## picket init

Set up Picket in a project.

```sh
picket init [--root <dir>] [--no-install]
```

## picket leave

Record a command the user runs after the item closes.

```sh
picket leave <id> --command "<command>" [--why "<why>"]
```

## picket list

List the work items with their lane, status, phases and next action.

```sh
picket list
```

## picket migrate

Move state from the old locations to .picket/.

```sh
picket migrate [--dry-run]
```

## picket mutate

Plant one mutant in the phase's code and check the tests catch it.

```sh
picket mutate <id>
```

## picket next

Print the next action for a work item, or for the latest open one.

```sh
picket next <id> | next --latest [--session <id>]
```

## picket open

Open a work item in a lane.

```sh
picket open --lane <fast|order|design|research> --title "<title>" [--text "<request>" | --request <file|->] [--ticket <KEY> --story <file>] [--id <id>]
```

## picket packet

Print the gate packet the lead shows the user.

```sh
picket packet <id> [--width <n>] [--json]
```

## picket preflight

Check the inputs, the tree and the tooling before a lane starts.

```sh
picket preflight <id>
```

## picket pullrequest

Review a pull request with the same summary a phase gets.

### picket pullrequest prepare

Fetch a pull request and summarize its diff for the reviewer.

```sh
picket pullrequest prepare <url> [--repo <path>]
```

### picket pullrequest post

Post a review file to a pull request as threads.

```sh
picket pullrequest post <url> --file <file> [--dry-run]
```

## picket route

Apply a verdict to a work item.

```sh
picket route <id> --verdict <TOKEN> --agent <name> [--phase <n>] [--scope <s>] [--through <n>] [--reason <r>] [--session <id>]
```

## picket set

Change a work item's status, blocked reason, branch, title or run grant.

```sh
picket set <id> <key>=<value>...
```

## picket source

Search a read-only source and bring its documents into a work item.

### picket source find

List the tracked files whose path contains a substring.

```sh
picket source find <name> <substring>
```

### picket source grep

Search every worktree and branch of a source with a regex.

```sh
picket source grep <name> <regex> [--path <prefix>]
```

### picket source pick

Choose one version of an ambiguous story reference.

```sh
picket source pick <id> <ref> <label>
```

### picket source add

Snapshot a reference into a work item after intake.

```sh
picket source add <id> <ref>
```

## picket state

Print a work item's derived state.

```sh
picket state <id>
```

## picket statusline

Print the Claude Code status line.

```sh
picket statusline
```

## picket style

Give Claude Code and the terminal the PicketAI look, or take it away.

### picket style apply

Install the theme, font, terminal colours and status line.

```sh
picket style apply [--only theme,font,terminal,statusline] [--dry-run] [--yes]
```

### picket style remove

Remove the styling items you choose, or all of them with --all.

```sh
picket style remove [--all [--dry-run]] [--yes]
```

## picket summary

Summarize a work item's diff, or a commit range, for the reviewer.

```sh
picket summary <id> [--base <ref>] | summary --range <base>..<head>
```

## picket uninstall

Remove Picket from a project: what init added, its state and, if chosen, work/.

Only the lead runs it; the Bash guard denies it to agents.

```sh
picket uninstall [--dry-run] [--yes] [--remove-work]
```

## picket verify

Check one phase against its must_haves.

```sh
picket verify <id> <phase> [--no-tests]
```

## picket waive

Record the user's approval of one silenced check.

Only the lead runs it; the Bash guard denies it to agents.

```sh
picket waive <id> --path <p> (--text "<added line>" | --deleted)
```
