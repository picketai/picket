## Phase 4 of 20261116-guard-hooks-each-get-a-closure: The edit target reads real paths

`editTarget` now computes `rel` and `outside` from the real paths of the root and the target. That closes group E1: a skip or comment written through a linked folder, inside the root or from outside it, is now read as the file it really is. `guard.scope` uses the target's `rel` and no longer has its own `realPath`. The new `edit target` closure passes, and `guard.scope` passes with six spellings per seed.

A plain `it(` through the link got no decision.

Decisions:
- `guard.scope` reads `target.rel` instead of importing `realPath`. Its old `relative(realPath(root), realPath(abs))` is now computed once in `editTarget`. That also applies `repoRelative`'s win32 case handling and `./` stripping to scope.
- `editTarget` takes `Pick<HookContext, "root">`, since it reads only the root; the tests pass a plain test context to it.
- The scope closure's path builders now take both folders (`{ root, elsewhere }`), not a module-level map, so the outside link has no hidden state.
- A link inside the root that points outside it now gives `outside: true`, so `guard.comments` and `guard.silenced` skip such a target. This is the real path, as D-005 sets out.
