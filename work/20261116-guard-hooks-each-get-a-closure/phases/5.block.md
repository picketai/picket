Root cause: comment forms other than a row's first line token and single block pair passed `guard.comments`, because each `LANGS` row held one line token and one block pair, and markup rows had no embedded script or style regions.

Verified: `picket check` gave CHECK OK (`npm test` passed with TMPDIR set to the scratchpad). `picket drive --run "node --test src/lib/hooks/guard/comments/index.variants.test.mts"` exited 0 (T-5.4). `picket verify 20261116-guard-hooks-each-get-a-closure 5` returned ok:true. `test/cli/lint-craft.test.mjs`, the mutate tests and `test/kernel/silenced.test.mjs` pass unchanged (T-5.3). With `comments.mjs` stashed, the closure listed C1 to C5 as open, plus `<style>` comments in `.html` and `.htm`. After `npm run build` I fed Write events to `dist/hooks/guard.comments.mjs`. It denied the `.vb`, `.php`, `.rb`, `.vue`, `.razor` and `.html` forms, and gave no decision for `#[Attribute]` in `.php`. Real `perl` accepted `=pod`/`=cut` and a trailing `# note`.

Decisions:
- `mutant.mts`, `silenced.mjs` and `lint.craft.mjs` check `lang === MARKUP` by identity, and the first two are outside the touch set. So every markup row in `LANGS` stays the `MARKUP` object. Script and style regions and the Razor block live in a per-extension table (`DOCUMENT_ROWS`) that only `commentLines` reads. `lint.craft.mjs` needed no change.
- A row now carries `lines` (token regexes, each with the character it must follow) and `blocks` (open and close pairs, `lineStart` for Ruby and Perl). `commentOf` takes whichever line token or block opener comes first on the line, so `<# note #>` reads as a block and not as a `#` line comment.
- The closure runs `guardComments`, which is async. So `openSpellings` and the closure family tests now await each run; the two `variants.test.mjs` tests that call `openSpellings` await it too.
- A `COMMENT_SYNTAX` row can carry a `head` line, used only for `.php` (`<?php`). Without it, `# note` would be HTML text and not PHP. I chose statements that are valid at top level (`const A: i32 = 1;` for Rust, `var a = 1` for Go).
- `comment placements` does not indent forms that must start at column 0 (`=begin`, `=pod`, a top-level `"""` docstring), because Ruby, Perl and Python refuse them indented. php, ruby, pwsh and the other compilers are not installed here (OQ-003); only perl ran.
