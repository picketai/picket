## Phase 1 of 20261116-guard-hooks-each-get-a-closure: Destructive roots get a closure

The new `guard.bash destructive roots` closure passes, and the two groups of spellings that were open at fdd3a2fa are now denied. Group B1 was ANSI-C and locale quoting: `$'rm'`, `$'\x72m'`, `$"rm"` and `git $'push'`. Group B2 was leading reserved words and redirections: `!`, `time`, `time -p`, `2>/dev/null`, `</dev/null`, `{ }`, and the `if`, `while`, `until` and `for` forms.

Root cause: `$'…'` command words fell through as a variable mark, and a leading keyword or redirection was read as the command root, because `shellText` copied ANSI-C quotes verbatim and `splitIntoSegments` had no notion of reserved words or leading redirections.

Verified: `picket check` gave CHECK OK (`npm test` passed with TMPDIR set to the scratchpad; see Decisions). `picket drive --run "node --test src/lib/hooks/guard/bash/judge.variants.test.mts"` exited 0 with all 7 tests passing (T-1.3). `picket verify 20261116-guard-hooks-each-get-a-closure 1` returned ok:true. I also fed PreToolUse events to the built `dist/hooks/guard.bash.mjs`: `$'\x72m' -rf build` and `time -p rm -rf build` were denied, `time git status` was allowed, and `{ ls; }` got no decision.

Decisions:
- I checked each `word quotings` and `command places` spelling in real bash with a stub command that prints its arguments. Every spelling ran the stub with the same arguments. `>/dev/null S` printed nothing only because it discards stdout. `w.exe` cannot run on Linux; it stays in `command paths` as the Git Bash spelling, the same way the existing name families use it.
- `word quotings` respells only the words of a command, never a leading assignment. A word that is already wholly quoted gets only the other quote forms. A word with a quote or `$` inside it that is not wholly quoted gets no respelling.
- `command paths` respells only the first command word.
- Phase 3 must handle one thing: the `w0''rest` and `$'\xHH…'` forms split the `{source}` placeholder when it starts a word, for example `$'\x7bsource}/a'`.
- The closure creates one project per test, not one per spelling (a WeakMap keyed by the test context), so it runs in about 200 ms.
- The closure calls `tableRows(...)` without a type argument because the phase grep `tableRows\(\w+, "..."\)` does not match `tableRows<string>(`.
- `npm test` fails one test on this machine (`test/cli/init.test.mjs`, "refuses the home folder") when TMPDIR is under the home folder. This is a known local issue, so check and verify ran with TMPDIR set to the scratchpad.
