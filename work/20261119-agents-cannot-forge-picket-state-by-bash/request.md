Fix guard.bash so a spawned agent cannot write the kernel's records under .picket/state/ through Bash. Today guard.scope stops an agent's Edit and Write there, but a Bash write gets through, because guard.bash treats all of .picket/state/ as a sanctioned log sink: echo '{...}' >> .picket/state/data/approvals.jsonl, tee -a, cp and node -e appendFileSync are all allowed for a developer agent. picket data run trusts approvals.jsonl, so an agent can forge the user's approval of a SQL file and the next picket data run executes SQL the user never read against a real database. The same gap lets an agent forge comments.jsonl and waivers.jsonl. Deny an agent's Bash write to the kernel's records under .picket/state/ (the data folder, comments and waivers at least), keep the scratch folder and the log files agents write today, keep the lead and the picket verbs able to write there, keep the guard's closure test closed and add its new seeds (CONTRIBUTING.md C-020). Also record in the data run row the digest that was approved, not one read again after the run (src/lib/verbs/data/run.mts:73).
