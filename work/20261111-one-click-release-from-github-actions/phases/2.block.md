## Phase 2 of 20261111-one-click-release-from-github-actions: One-click release, latest and retag in release.yml

`release.yml` can now release from a manual run on `trunk`. The new first job, `version`, works out the mode from the trigger, makes and pushes the release commit and tag, and hands every later job a `ref` and a `tag`. The `publish` job moves `latest` after it publishes, and the new `retag` job moves only `latest`. No `run:` block contains `${{`; every input and job output reaches the shell through `env`.

Decisions:
- The design asked for two checkouts in the `version` job: the dispatched commit for a dry run, and `trunk` with full history for a release. I wrote them as two steps with their own `if`, not one step with conditional `with:` values. A `fetch-depth` of `0` is falsy in an Actions expression, so `cond && 0 || 1` would always give 1.
- The tag-push mode reads the tag from `GITHUB_REF_NAME` in the environment, not from `${{ github.ref_name }}`, which follows D-006.
- In the drive, the git identity came from the `GIT_AUTHOR_*` and `GIT_COMMITTER_*` variables, because the guard denies `git config` in scratch repositories. The identity step itself was not driven.
- `release.yml` was rewritten as a whole file. Both `run: npm publish` lines are byte for byte as before, and T-5.5 pins them.
