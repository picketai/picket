Release from GitHub with one click. In .github/workflows/release.yml, a manual run (workflow_dispatch, no input needed) does the whole release in one run: a new version job (contents: write) checks out trunk, refuses unless CHANGELOG.md's newest heading ends "(not released yet)", renames that heading to the bare version, commits it, runs npm version prerelease --preid alpha (whose existing hook syncs src/.claude-plugin/plugin.json), and pushes the commit and the v tag; then test, build-on-22 and mods run on that tag's commit, and publish publishes it under the alpha dist-tag. Everything stays in release.yml, because the npm trusted publisher is bound to that file and a tag pushed with GITHUB_TOKEN would not start another workflow. A pushed v tag still releases as today. After every publish, the publish job also runs npm dist-tag add @picketai/picket@<version> latest (the trusted publisher has the npm dist-tag permission). Add an optional workflow_dispatch input retag_latest: <version> that, when set, only moves latest to that already-published version (to move latest to 1.0.0-alpha.6 now). The changelog check and rename live in .github/scripts/release.mjs as verbs with unit tests. Update the release section of CONTRIBUTING.md. The current dry-run-by-hand behaviour may be replaced by an input if needed. User said: go, don't gate.

## Brief
purpose: Release Picket from GitHub with one manual run: bump, tag, publish and move latest, without a local npm login
in scope: release.yml version job, publish in the same run, dist-tag latest after publish, retag_latest input, changelog check and rename verbs in release.mjs with tests, CONTRIBUTING.md release section
out of scope: generated changelogs (release-please, semantic-release), PR-based releases, branch protection, other workflows, the npm trusted publisher settings
