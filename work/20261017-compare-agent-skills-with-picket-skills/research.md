# Report: Compare agent-skills with Picket skills

## Summary
agent-skills is 25 Markdown skills by lifecycle phase with four review personas, nine commands, three optional bash hooks, shared checklists and a three-tier eval, and it enforces nothing at run time [VERIFIED]. Picket is a kernel plus four lane agents where code decides lane, state, verification and verdict routing and twelve wired hooks deny or bounce violations [VERIFIED]. agent-skills does better at five things: measuring its own skills (a free trigger and routing check, pressure-scenario fixtures, a validated model grader), teaching domain content Picket has none of (debugging, observability, CI/CD, migration technique, API and idempotency design, frontend and accessibility, performance, shipping), repeating untrusted-content rules in seven skills, a documented contributor and adoption path, and packaging for about ten hosts [VERIFIED]. Picket does better at enforcing what it teaches, guarding the agent's own commands, verifying a phase by running it, and measuring cost and determinism, but it carries stale duplicates of its review checklists, a ledger that never records cost, and no guard against silenced checks [VERIFIED]. The approaches differ in kind: agent-skills persuades the model with checklists and anti-rationalization tables, Picket constrains it with code [INFERRED].

## Context
Asked: compare agent-skills (skills, agents, hooks, commands, evals) with Picket, say what it does better, what Picket can learn, how the approaches differ, and every improvement available, thoroughly. The lead's redirect, "do not leave anything out", asked for every previously unread source to be read in full; this pass did that for agent-skills and for Picket's kernel libraries, skills, docs and rules. Paths prefixed `AS:` are under the agent-skills root named in the frontmatter; unprefixed paths are in this repository. This report describes sources and gives no design. What was still not read is listed under Risks and unknowns.

## Structure
AS: `skills/` (25 directories, 343 KB of SKILL.md, 9 to 21 KB each, plus 4 supporting reference files), `agents/` (4 personas), `commands/` (9 TOML mirrored for Claude and Gemini), `hooks/` (3 bash hooks, each with a shell test), `references/` (7 shared checklists), `evals/` (25 case files, 41 fixture files totalling 23 KB, 5 plugin cases), `scripts/` (validators and the eval runner, about 250 unit tests), `docs/` (17 files including 10 host guides), `.github/` (one CI workflow with a Windows and macOS matrix, an issue template).

Picket: `core/skills` (16 skills, 61 KB of SKILL.md, each with `steps/` of at most 80 lines), `core/agents` (4), `core/hooks` (12 shells over `core/lib/hooks`), `core/lib` (kernel, about 230 KB), `core/rules` (4 injected), `core/bin/picket.mjs` (28 verbs), `bench/` (14 tasks, one fixture, code-only graders), `test/` (kernel, hooks, budgets, markdown paths, release), `docs/` (agents, skills, how-to, design snapshots).

Flow in AS: the user picks a command or the host matches a skill description; the skill's process and checklists are the only control. Flow in Picket: `picket admit` computes a lane, the lane skill reads one step file at a time as `picket next` directs, agents end on a verdict token, hooks route it into `work/<id>/`.

## Findings
### Approach and architecture
- **R-001** [VERIFIED] agent-skills has no state machine: its router is a decision tree in a skill and the commands map one to one to phases. Picket's lane choice, state and verdicts are code. `AS:skills/using-agent-skills/SKILL.md` (Skill Discovery), `core/skills/researching/SKILL.md`.
- **R-002** [VERIFIED] agent-skills ships a three-tier eval: structural validators, a deterministic TF-IDF trigger and routing check with a CI floor (`--min-rank1 95`), and behavioural runs through headless `claude`; plus `claude plugin eval` cases with and without the plugin. `AS:evals/README.md`.
- **R-003** [VERIFIED] The eval README records that skill firing is stochastic (review skill fired 5 of 7 runs, TDD 2 of 7) and that rewording one description moved firing from 0 of 6 on three realistic prompts. This is measured evidence on description quality; Picket has not measured any skill description this way. `AS:evals/README.md` (plugin evals section).
- **R-004** [VERIFIED] Picket's bench measures the harness: pass@1, pass^k, route agreement, cost CV, cache ratio, stops, re-reads, with `--check` failing beyond two standard errors. The clean comparison shows 14 of 14 tasks passing against trunk's 13, cost $2.97 against $3.37 per task, first reviewable output 96 s against 130 s. Only the 6 fast tasks have n=3; the 8 order, design and research tasks have n=1, so pass^k and cost CV mean little there. agent-skills has no cost or determinism metrics. `bench/README.md`, `bench/results/comparison-clean.md`.
- **R-005** [VERIFIED] agent-skills applies a core-behaviours block at all times (surface assumptions, stop on confusion, push back, enforce simplicity) through the meta-skill. Picket injects four rules at SessionStart and SubagentStart instead. `AS:skills/using-agent-skills/SKILL.md`, `core/hooks/README.md` (inject.rules).
- **R-006** [VERIFIED] agent-skills covers lifecycle areas with no Picket skill: idea refinement, API design, frontend, debugging, security depth, performance, CI/CD, observability, deprecation and migration, shipping, git and release versioning. Picket's 16 skills are lane, artifact and tooling oriented. `core/.claude-plugin/plugin.json`, `AS:skills/`.
- **R-007** [VERIFIED] agent-skills packages for many hosts (`.claude-plugin`, `.codex-plugin`, `.agents`, `.gemini/commands`, `.opencode`, ten host guides with troubleshooting tables) and its `AGENTS.md` maps intent to skills for hosts with no slash commands; the `npx skills` CLI installs into 70 or more agents. A per-skill install loses the shared `references/` (issue 361). Picket targets Claude Code only. `AS:README.md`, `AS:docs/*-setup.md`, `core/.claude-plugin/plugin.json`.
- **R-008** [VERIFIED] agent-skills publishes an honest comparison against Superpowers and Pocock's skills, a "how to decide" section, a note on what none of them solved (durable cross-session memory), and a cited single-task experiment. Picket's README compares only against its own previous harness (clean run of 2026-09-14), not against other frameworks. `AS:docs/comparison.md`, `README.md` (Status).
- **R-009** [VERIFIED] Picket's reviewer contract is stricter: read-only, no finding without `file:line` read this pass, try-to-disprove, failure scenario required for Critical and Major, fixed output block, exact verdict tokens routed by hooks. `core/agents/reviewer.md`, `core/skills/reviewing/SKILL.md` (Evidence bar).
- **R-010** [INFERRED] agent-skills' guarantees rest on model compliance; Picket's rest on hook denial. Picket pays with a 37k-token prompt per invocation and gate stops; agent-skills has neither cost nor enforcement. `bench/README.md` (Cost of running it), `AS:docs/comparison.md`. ### Skill content, anatomy and authoring
- **R-011** [VERIFIED] Every AS skill carries Overview, When to Use, Common Rationalizations, Red Flags and Verification, and the lint requires them. A grep for "rationaliz" and "red flags" over `core/` returns no hit. Picket skills are routing indexes; the counters to skipped steps are hooks and reviewer rows. `AS:docs/skill-anatomy.md`, `AS:scripts/lib/skill-lint.js:49`, `core/skills/`.
- **R-012** [VERIFIED] Lint rules differ: AS requires named sections, a description of at most 1024 characters with a "Use when" clause that is not negated, spec-only frontmatter keys, and warns above 500 lines. Picket enforces line budgets (SKILL 150, step 80, agent 120, rule 60, CLAUDE.md 2048 bytes, hook cold start 200 ms) and a "Use when" clause. `test/budgets.test.mjs:15-23`, `AS:scripts/lib/skill-lint.js`.
- **R-043** [VERIFIED] "Write the procedure, not the workaround": a skill step needing a model or private tool name belongs in an issue, citing WikiSkill (arXiv:2608.27454), and only spec keys may sit at the top level of frontmatter because a strict host (Cursor, issue 494) rejected the file. Picket skills use Claude Code keys (`user-invocable`, `disable-model-invocation`) and agents declare `model` and `effort`, by design a single-host harness. `AS:docs/skill-anatomy.md`, `AS:docs/advanced-per-agent-configuration.md`, `core/skills/*/SKILL.md`, `core/agents/*.md`.
- **R-044** [VERIFIED] AS lints personas as well as skills (a closing Composition section, the three rules in `docs/agents.md`) in the same `validate-skills.js` run, and tests every validator. Picket caps agent length but does not lint agent content. `AS:scripts/validate-skills.js:58-77`, `test/budgets.test.mjs`.
- **R-045** [VERIFIED] 25 AS SKILL.md files total 343 KB (average 13.7 KB, up to 21 KB); 16 Picket SKILL.md files total 61 KB (average 3.8 KB, up to 10.4 KB for `reviewing`), with procedure in step files of at most 80 lines loaded one at a time. Measured with `wc -c`. `AS:skills/*/SKILL.md`, `core/skills/*/SKILL.md`.
- **R-046** [VERIFIED] AS skills tell the agent not to repeat a successful build or test command without an intervening change, as a rationalization row and a red flag in two skills. Picket measures re-reads in the bench and flags look-around stalls with `monitor.context`. `AS:skills/test-driven-development/SKILL.md`, `AS:skills/incremental-implementation/SKILL.md`, `bench/README.md`, `core/hooks/README.md`.
- **R-075** [VERIFIED] Picket has skills agent-skills lacks: explaining (worked data, markers, a `Not known` section), proofreading (five passes, levels L0 to L3, report before change), summarizing (PR description under 4000 characters, counted mechanically), ticketing (Jira, every write confirmed), branching (worktrees and submodules, a removal ladder), resuming, inspecting, benchmarking, documenting with Word export. AS's prose review is one paragraph. `core/skills/{explaining,proofreading,summarizing,ticketing,branching}/SKILL.md`, `AS:skills/documentation-and-adrs/SKILL.md` (Prose Review).

### Evals, tests and CI
- **R-013** [VERIFIED] The Tier 2 routing check: stemmed TF-IDF over name (weighted twice) and description; each skill needs at least 3 positive and 2 negative prompts, negatives carry an `owner` that must outrank the skill; two descriptions at cosine 0.5 warn and 0.75 fail; a rank-1 ratchet. It runs in milliseconds with no model call. `AS:scripts/run-evals.js:1-60`, `AS:evals/README.md` (Eval case format).
- **R-014** [VERIFIED] Tier 3 behavioural evals run a skill in a throwaway git repository with fixtures and grade the stream-json trace against written `expectations[]` with a model grader, traces fenced as untrusted. Picket's bench never grades a single skill in isolation. `AS:evals/README.md`, `bench/README.md` (How a run works).
- **R-015** [VERIFIED] `claude plugin eval` runs each case twice, with and without the plugin, and excludes a `tool_used: Skill` grader from the score in the two-arm run, so skill lift is measured on the reply. Picket's bench has `trunk` and `plugin` arms at suite level. `AS:evals/README.md` (Plugin evals), `AS:plugin.json` (`experimental.evals`), `bench/README.md` (adapters).
- **R-016** [VERIFIED] agent-skills keeps an append-only ledger of rejected skill changes with rank-1 scores (currently empty), a pre-flight for new skills (search catalogue, open PRs, ledger, justify the gap), a path-scoped rule, a `skill-gap` issue template and a developer onboarding with a verification loop. Picket has CONTRIBUTING, `harness-authoring.md` and 20 or more dated run files under `bench/results/` as an informal history, but no pre-flight for a new skill and no rejected-change ledger. `AS:evals/skill-impact.md`, `AS:CONTRIBUTING.md`, `AS:docs/developer-onboarding.md`, `CONTRIBUTING.md`.
- **R-017** [VERIFIED] agent-skills CI runs on every push and pull request: skill lint, version sync, routing evals, reference links, command parity, hook payload tests, a Windows and macOS rerun of the validators, `claude plugin validate .` and a marketplace install. Picket's only workflow is `release.yml` (tag or manual), which runs `npm test` before publishing; `package.json` has `claude plugin validate --strict` scripts for the three mods but none for `core`. `AS:.github/workflows/test-plugin-install.yml`, `.github/workflows/release.yml`, `package.json:41-43`.
- **R-061** [VERIFIED] AS fixtures hold pressure scenarios with a trap and an expectation that the agent holds the line: a tech lead dictates a remainder-dump patch with ten minutes left; a sponsor demands GO over a failing checkout test and no rollback plan; a stakeholder wants a patch without reproduction; a team calls a two-day untested draft sunk cost; a migration plan carries five unproven claims. Picket's 14 bench tasks are all cooperative requests. `AS:evals/fixtures/{shipping-and-launch,debugging-and-error-recovery,incremental-implementation-pressure,doubt-driven-development}/`, `AS:evals/cases/test-driven-development.json` (eval 2), `bench/tasks/`.
- **R-062** [VERIFIED] AS fixtures total 23 KB over 41 files for 25 skills; each is a few lines with one planted flaw (a pagination off-by-one, an SSRF-prone fetch, a LIKE query built from user input) and the stack varies (one case uses a Python ledger). Picket reuses one 24-file TypeScript service for all 14 tasks, so every result is TypeScript only. `AS:evals/fixtures/`, `bench/README.md` (How a run works).
- **R-063** [VERIFIED] Grading differs. AS asks a model to grade a trace against numbered expectations, then validates the grader's JSON in code: ids bound to 1..n, no duplicates, blank evidence rejected, counters and pass rate recomputed rather than trusted, raw output kept on rejection. Picket's graders are code only (hidden vitest files, file and grep assertions, report headings and mentions), so results are reproducible but prose and review quality are not graded. `AS:scripts/run-evals.js` (parseGrading), `bench/lib/grade.mjs`, `bench/tasks/research-11-pricing.json`.
- **R-064** [VERIFIED] Tier 3 injects the skill's full text with `--append-system-prompt`, so a behavioural eval never tests whether the skill triggers. Triggering is covered by the lexical Tier 2 and by five plugin cases that touch two skills (review and TDD); firing of the other 23 skills is unmeasured. `AS:scripts/run-evals.js` (runBehavioral), `AS:evals/plugin/`.
- **R-065** [VERIFIED] AS has about 250 unit tests over its tooling (skill-lint 762 lines, run-evals 830, 12 floor-guard cases, 15 sdd-cache and 18 simplify-ignore shell cases) run on three operating systems. Picket's tests cover the kernel, hooks, budgets, Markdown paths and release, run on Linux on tag only. `AS:scripts/*-test.js`, `AS:hooks/*-test.sh`, `test/`.
- **R-066** [VERIFIED] AS keeps parallel artifacts in step with validators: command descriptions across three directories, SPEC.md and tasks paths across 13 files after a real regression, `references/` links including `#anchor` slugs, five manifest versions. Picket's equivalents are `test/markdown-paths.test.mjs` (backticked paths exist) and `release.mjs sync-version` (four manifests); the test files in `test/` include none that compares `docs/skills.md` with the SKILL.md descriptions it repeats. `AS:scripts/validate-*.js`, `CONTRIBUTING.md` (Markdown).
- **R-076** [INFERRED] The 14 bench tasks cover the four lanes (6 fast, 4 order, 2 design, 2 research) but not a bug fix with a reproduction test, a refactor, a review of a pasted diff, a documentation task or a plain question that must take no lane. AS has "stays quiet" cases for exactly that last shape. `bench/tasks/`, `AS:evals/plugin/code-review-stays-quiet*`, `CLAUDE.md` (rule 1).
- **R-077** [INFERRED] All lane routing is about 15 regular expressions in `admit.mjs` over the request text, with a forced `lane:` override and a security override; its accuracy is measured only by the 14 bench prompts and `test/kernel/admit.test.mjs` (not read). AS measures routing on 100 or more labelled prompts with a 95 percent rank-1 floor. `core/lib/admit.mjs`, `AS:evals/cases/`.

### Roles, orchestration, commands and hooks
- **R-018** [VERIFIED] agent-skills states one orchestration rule (the user or a command orchestrates, personas never call personas, depth at most 1) and a catalogue with named anti-patterns (router persona, persona chains, paraphrasing orchestrators, deep trees). `/ship` fans out three personas in one turn and merges in the main agent. Picket's lead continues named agents by `SendMessage`, the design lane runs developer and reviewer cross-check concurrently, and no lane fans out independent reviewers. `AS:references/orchestration-patterns.md`, `AS:commands/ship.toml`, `core/skills/designing/SKILL.md`.
- **R-019** [VERIFIED] `AS:references/orchestration-patterns.md` documents Agent Teams for competing-hypothesis debugging (teammates challenge each other) and says not to wrap it in a subagent fan-out. No Picket skill describes an investigation mode with adversarial teammates. `AS:references/orchestration-patterns.md` (Worked example).
- **R-020** [VERIFIED] AS personas are perspectives on one artifact (code-reviewer, security-auditor, test-engineer, web-performance-auditor); Picket agents are roles in a process (analyst, architect, developer, reviewer). Picket's security view is a checklist loaded into the one reviewer. `AS:docs/agents.md`, `core/agents/reviewer.md`, `core/skills/reviewing/SKILL.md` (Load table).
- **R-023** [VERIFIED] AS verdicts (APPROVE or REQUEST CHANGES, GO or NO-GO) are prose; nothing routes them. Picket's tokens are checked by `guard.block` and applied by `route.verdict`. `AS:commands/ship.toml`, `core/hooks/README.md`.
- **R-024** [VERIFIED] Entry differs. AS: nine commands, one per phase, user-chosen. Picket: `picket admit` computes the lane from regex signals and repository probes (security, migration, irreversible, new dependency, cross-context), a forced lane is honoured except a security path wins. `AS:commands/*.toml`, `core/lib/admit.mjs`.
- **R-025** [VERIFIED] `/build auto` needs an existing SPEC.md, a clean `git status --porcelain` baseline, one approval of the plan, then per-task RED, GREEN, regression, build and one commit staging only touched files; it stops on a failing test, an ambiguity, or an irreversible step. Picket's counterpart is the run grant at a gate, never spanning a security or irreversible phase, with the kernel committing on approval. `AS:commands/build.toml`, `core/rules/work-items.md`, `core/lib/route.mjs`.
- **R-026** [VERIFIED] AS hooks are optional and user-wired in bash with `jq`: a session-start router injector (deliberately unwired), a WebFetch cache (`sdd-cache`), and a block-hiding hook (`simplify-ignore`, 18 KB of bash with lock directories, backups, a Stop expander and recovery files). Picket's twelve hooks are all registered in `hooks.json` and enforce. `AS:hooks/*.sh`, `core/hooks/hooks.json`.
- **R-027** [VERIFIED] `sdd-cache` stores each fetched page keyed by URL and serves it only after an HTTP 304 revalidation, never caches pages without validators, and shows the original prompt on a hit. Picket's analyst has `WebFetch` and `WebSearch` and no fetch cache. `AS:hooks/sdd-cache-pre.sh`, `AS:hooks/SDD-CACHE.md`, `core/agents/analyst.md`.
- **R-028** [VERIFIED] `simplify-ignore` replaces annotated blocks with `BLOCK_<hash>` placeholders on Read and restores them on Edit, Write and Stop, with documented limits. Picket has no read-time redaction hook. `AS:hooks/simplify-ignore.sh`, `AS:hooks/SIMPLIFY-IGNORE.md`.
- **R-060** [VERIFIED] Picket guards the agent's own commands; AS does not. `guard.bash.mjs` (1273 lines plus a vendored tokenizer) evaluates compound commands, heredocs, substitutions, variable taint and write redirects, has a separate PowerShell reader, a read-only allowlist, a destructive deny list, an escalation marker that asks the user once and logs the outcome, and a read-only guard for declared sources. AS safety content is advice inside skills. `core/lib/hooks/guard.bash.mjs`, `core/lib/powershell-text.mjs`, `core/lib/escalation.mjs`.
- **R-067** [VERIFIED] Picket has an extension mechanism: `.picket/extensions/<name>/extension.json` adds rules, role notes, review steps and preflight checks, with a 10,000 character injection cap, path confinement, refusal reporting and a ban on verdict lines in extension text. AS has no extension point beyond user-level agent definitions that override the plugin's and per-agent adapter files. `core/lib/extensions.mjs`, `core/lib/extension.schema.json`, `AS:commands/ship.toml` (Persona resolution).
- **R-069** [VERIFIED] Router discipline. AS warns that two routers fight, leaves its session-start hook unwired, and its `AGENTS.md` tells OpenCode to invoke a skill on "even a 1% chance" and lists thoughts to ignore ("too small for a skill", "I'll gather context first"). Picket's single router is code: `CLAUDE.md` tells the lead to run `picket admit` and load one lane skill, never a second; a plain question takes no lane. `AS:docs/getting-started.md`, `AS:AGENTS.md`, `CLAUDE.md`.
- **R-070** [VERIFIED] Picket shows which skill fired: `picket statusline` reads the last `Skill` tool call from the transcript, and the ledger records agent, lane, work id and verdict per turn. AS can observe a skill firing only through the `tool_used: Skill` grader of an eval. `core/lib/statusline.mjs` (lastSkill), `core/lib/hooks/emit.ledger.mjs`, `AS:evals/plugin/`.

### Review, testing, security and quality content
- **R-021** [VERIFIED] Security content differs in depth. AS: threat model first, STRIDE per boundary, abuse cases, three-tier Always/Ask/Never, SSRF, IDOR, rate limiting, dependency and supply-chain triage, privacy, LLM Top 10. Picket: four rows (Se1 secret, Se2 injection, Se3 insecure default, Se4 guard bypass) plus a security-paths rule that is stronger on process (forced design lane, no run grant, mandatory drive). `AS:skills/security-and-hardening/SKILL.md`, `AS:agents/security-auditor.md`, `core/skills/reviewing/steps/30-patterns-security.md`, `core/rules/security-paths.md`.
- **R-022** [VERIFIED] AS review adds ideas the Picket reviewer lacks: a mutation experiment (invert one condition, run the suite, a green run is a finding), named structural remedies, change-size targets (about 100, 300, 1000 lines), dependency upgrade discipline, presumptive blockers. It also asks for praise and has no evidence bar. `AS:skills/code-review-and-quality/SKILL.md`, `AS:agents/code-reviewer.md`.
- **R-029** [VERIFIED] Untrusted-content rules appear in seven AS skills: browser output, error messages, fetched docs, config and data files, third-party API responses, LLM output. A grep of `core/skills`, `core/agents` and `core/rules` for "untrusted", "prompt injection" and "instruction-like" finds none outside `explaining`, which treats fetched web text as data, although the analyst also fetches pages and tickets. `AS:skills/{debugging-and-error-recovery,source-driven-development,context-engineering,test-driven-development,security-and-hardening,browser-testing-with-devtools,api-and-interface-design}/SKILL.md`, `core/skills/explaining/SKILL.md`.
- **R-034** [VERIFIED] A project-wide Definition of Done is a separate shared reference applied on top of per-task criteria. Picket's per-phase `Done when` criteria are checked by code, and the standing floor (comments, test scope, security) lives in reviewer rows Cm1, Cm2, Ts1 to Ts4, Se1 to Se4 and the developer craft bar. `AS:references/definition-of-done.md`, `core/skills/reviewing/steps/10-alignment.md`.
- **R-035** [VERIFIED] `constraint-driven-development` writes `CONSTRAINTS.md` (floor, enforced numbers with the command that checks each, measured-only ratchets, exceptions with owner and expiry), places checks by cost, names five weakened-bar moves to look for in the diff, and ranks checks as external, project or suite. Picket overlaps in `picket check`, `guard.comments`, Cm1, Ts rows and the bench `--check` ratchet; it has no project quality-bar file with numbers and no skipped or deleted test detector. `AS:skills/constraint-driven-development/SKILL.md`, `AS:commands/constraints.toml`, `core/hooks/README.md`.
- **R-036** [VERIFIED] `doubt-driven-development` sends a small artifact and its contract (never the author's claim) to a fresh-context reviewer with an adversarial prompt, classifies each finding (contract misread, actionable, trade-off, noise), caps at 3 cycles, offers a cross-model second opinion, and names "doubt theater" as a red flag. Picket spawns a fresh `cumulative-reviewer` once, at the end, and treats three rounds of drift or change requests as a user decision. `AS:skills/doubt-driven-development/SKILL.md`, `core/skills/ordering/steps/40-review.md`, `CLAUDE.md` (rule 3).
- **R-037** [VERIFIED] agent-skills has a `debugging-and-error-recovery` skill (stop the line, reproduce, localize, reduce, fix the root cause, guard, verify; bisect; a non-reproducible decision tree). Picket has no debugging skill; a bug is admitted as a fast change or a research question, and the files read hold no red-first or reproduction-test step. `AS:skills/debugging-and-error-recovery/SKILL.md`, `core/skills/expediting/SKILL.md`, grep over `core/`.
- **R-038** [VERIFIED] Testing stances differ. AS prefers real implementations over fakes, stubs and mocks, and wants integration and E2E tests at boundaries; the Prove-It pattern puts a failing test first. Picket restricts the developer to unit and architecture tests, flags integration tests as Ts1 and infrastructure in a unit test as Ts2, and has no red-first rule. `AS:skills/test-driven-development/SKILL.md`, `core/agents/developer.md` (Constraints), `core/skills/reviewing/steps/10-alignment.md` (Test scope). ## Glossary
- **Anti-rationalization table**: a skill section listing excuses an agent makes to skip a step, each with a rebuttal.
- **pass^k**: probability that all k runs of a task pass, a determinism measure.
- **TF-IDF**: a text score that ranks a document by how many rare query words it shares; used by AS to rank skill descriptions against a prompt.
- **Ratchet**: a recorded measurement that must not get worse, used when no target number is chosen.
- **Persona**: an agent defined by a perspective and an output format, one artifact at a time (AS term).
- **Run grant**: Picket's approval that covers several phases without a gate, never crossing a security phase.
- **Expand/contract**: a schema change shipped as additive steps first and a separate destructive step last, so old and new code stay valid together.
- **Idempotency key**: a client-chosen label that lets a server recognise a retried request and return the first result instead of acting twice.
