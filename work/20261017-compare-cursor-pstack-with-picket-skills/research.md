# Report: Compare cursor pstack with Picket skills

## Summary
pstack is 54 Markdown skills (30 workflow skills and 24 one-rule principles), 23 playbooks behind one router skill, two agents, a dormant Slack automation pack and about 7,000 lines of Bun and TypeScript tooling, and it ships no hooks and no always-on rules, so everything it asks of the model is enforced by prose, a todo list and scripts the model chooses to run [VERIFIED]. Picket is a kernel plus four lane agents where code picks the lane, the next action, verification and verdict routing and twelve hooks deny or bounce violations, so the two differ in kind: pstack persuades and parallelises, Picket constrains and gates [VERIFIED]. pstack does better in six areas Picket has no lane or skill for: bug reproduction with a red-first commit order, parallel and multi-model design and review (architect, arena, swarm, interrogate), the whole pull request life (open, babysit with a typed watcher, independent verification, landing), unattended and program-scale runs with a decision trail, project-local verification skills with a feature map, and loops that turn repeated mistakes and finished sessions into repository or skill changes [VERIFIED]. Picket does better where pstack states no check at all: command guarding, state and next action in code, schema lint, a security-path rule, a measured benchmark with cost and determinism, a stricter review evidence bar, and a dependency-free kernel [VERIFIED]. pstack's multi-model and cloud features are Cursor features that its own Claude Code adapter drops or degrades, and its README reports no measured result, so its effect on outcomes is not established by the sources [VERIFIED].

## Context
Asked: compare pstack's skills, agents, automations, hooks, docs and plugin manifest with Picket's, say what it does better, what Picket can learn, and how the approaches differ, thoroughly, with a deep pass that leaves nothing out. This report was written in one turn from an outline and a deep pass, as the lead directed. Paths prefixed `PS:` are under the pstack root named in the frontmatter, `CP:` under the cursor/plugins root, and unprefixed paths are in this repository. Where pstack and the agent-skills report share an idea it is noted in one line. The report describes sources and gives no design; findings that need a decision carry `[ARCHITECT REVIEW NEEDED]`. What was not read is under Risks and unknowns.

## Structure
PS: `skills/` (54 directories, 195 KB of SKILL.md, none over 156 lines; `poteto-mode` at 149 lines and 20.5 KB with `playbooks/` of 23 files, `references/bugbot-triage.md` and `scripts/` of Bun TypeScript), `agents/` (2), `automations/benny/` (a dormant pack that setup copies into a target repository), `docs/guide/` (10 pages and an index, 6 JPEG illustrations), `docs/harness/claude-code.md` (a name-mapping table), `plugin.json` and `.cursor-plugin/plugin.json`, `assets/logo.png`. 170 files in total.

Flow in pstack: the user picks `/poteto-mode` (or a skill) from the slash menu; the model matches a playbook, copies its steps into a todo list, reads principles and other skills by path as steps fire, and spawns `poteto-agent` delegates on a model chosen per role. Flow in Picket: `picket admit` computes a lane, the lane skill reads one step file at a time as `picket next` directs, agents end on a verdict token and hooks route it into `work/<id>/`.

## Findings
### Approach and architecture
- **R-001** [VERIFIED] pstack runs no code on its own. The Cursor manifest declares only `skills` and `agents`, the plugin schema allows `hooks` and `rules`, and the plugin has no hooks directory. The only things that execute are scripts a skill tells the model to run (`check-plan.mjs`, `orch`, `watch-pr`, `worktree-audit.sh`, `log.sh`). Picket registers twelve hooks in `core/hooks/hooks.json`. `PS:.cursor-plugin/plugin.json:29`, `CP:schemas/plugin.schema.json:85-89`, `core/hooks/README.md:3-19`.
- **R-002** [VERIFIED] The control mechanism differs in kind. pstack's rules are text plus a todo list whose first items are the matched playbook's steps "copied in verbatim", with a skipped step staying visible as `skip: <reason>`. Picket's equivalents are `picket next`, `picket verify` and hook denials. pstack's own agent file concedes the weakness: substituting a generic subagent "skips that read and drifts". `PS:skills/poteto-mode/SKILL.md:123`, `PS:agents/poteto-agent.md:3`, `CLAUDE.md:7-10`.
- **R-003** [VERIFIED] Routing is model judgment in pstack and code in Picket. `poteto-mode` lists 23 playbooks and the model matches one; Picket's `admit.mjs` scores roughly fifteen regular expressions and repository probes into four lanes. pstack's playbooks cover work Picket has no lane for: forensics, hillclimb, prototype, visual parity, babysit, shipping, autopilot, orchestrate, session pickup, pause, worktree cleanup. `PS:skills/poteto-mode/SKILL.md:121-146`, `core/lib/admit.mjs:18-33`.
- **R-004** [VERIFIED] pstack makes 53 of 54 skills explicit-only (`disable-model-invocation: true`); only `setup-pstack` is model-invocable. The router reads every other skill by path, and the Claude Code adapter says the `Skill` tool "refuses most pstack skills". Skill firing therefore never depends on description matching. Picket skills carry long trigger descriptions and are model-invocable except `summarizing`. `PS:docs/harness/claude-code.md:12`, `core/skills/expediting/SKILL.md:1-13`, `core/skills/summarizing/SKILL.md:1-5`. Same concern as agent-skills' firing measurements (R-003 of that report).

### Distribution, validation and tests
- **R-013** [VERIFIED] pstack is published from a multi-plugin marketplace repository. Cursor uses `pstack/` directly; Claude Code installs a generated, committed copy at `harness/pstack/claude-code`, built by `generate-pstack-harness-trees.mjs`. A table of 22 Cursor terms makes the generator fail unless the adapter has a row for every one a skill uses, and `--check` fails CI when the committed tree drifts. `CP:scripts/generate-pstack-harness-trees.mjs:27-50`, `CP:.github/workflows/validate-plugins.yml:31`, `PS:README.md:30`.
- **R-014** [VERIFIED] The marketplace repository validates on every pull request that touches pstack: ajv schema checks, marketplace-to-manifest name match, and an error when `.cursor-plugin/plugin.json`, `.claude-plugin/plugin.json` and `plugin.json` carry different versions. Picket's only workflow is `release.yml` on a tag, running `npm test`. `CP:scripts/validate-plugins.mjs:140`, `CP:.github/workflows/validate-plugins.yml:3-14`, `.github/workflows/release.yml:44`.
- **R-015** [VERIFIED] pstack tests only its scripts: `bun test` over `orch`, `watch-pr` and `check-plan.test.ts`, plus `tsc --strict` and compile-time proofs with `@ts-expect-error` for impossible verdict shapes. No lint, trigger check or eval covers the 54 skills; the authoring playbook says to validate frontmatter and links and to "test cases if structural", with no script behind it. Picket's budgets test fails on skill, step, agent, rule and hook limits. `PS:skills/poteto-mode/scripts/package.json:5-6`, `PS:skills/poteto-mode/scripts/watch-pr/types.compile.ts:76`, `PS:skills/poteto-mode/playbooks/authoring-a-skill.md:5-7`, `.claude/rules/harness-authoring.md:12`.
- **R-016** [VERIFIED] The eval playbook is a procedure with no runner: sanitise directory and slug names, never use the words eval, test, judge or candidate where the candidate can see them, ask for an organic prompt, run N candidates, read each candidate's transcript to see which files it opened (not what it claims), use one blinded judge, then read every output yourself. Picket's bench is code that grades by assertion. `PS:skills/poteto-mode/playbooks/eval.md:5-31`, `bench/README.md:19-24`.
- **R-017** [VERIFIED] pstack reports no cost or determinism figure. Its guide says extra tokens are "the price of the rigor" and offers levers (a smaller budget, `auto` roles, a shorter panel list). Picket's bench reports pass@1, pass^k, cost per task and cache ratio, and its README quotes $2.97 per task against $3.37. `PS:docs/guide/01-setup.md` (Keep the cost in check), `bench/README.md:35-49`, `README.md:56-70`.
- **R-018** [VERIFIED] pstack's TypeScript tooling needs Bun and a downloaded dependency. `bootstrap.ts` runs `bun install --frozen-lockfile` into the skill directory on first use, writes an install key, and re-executes the command. Picket's `core/` imports only Node built-ins and relative files (grep of `core/lib/*.mjs` and `core/bin/picket.mjs` found no other import). `PS:skills/poteto-mode/scripts/bootstrap.ts:30-65`, `PS:skills/poteto-mode/scripts/package.json:11-13`.

### Understanding and investigation
- **R-019** [VERIFIED] `how` and `why` are paired read-only skills. `how` sizes the question: a narrow one gets a single explainer, a subsystem gets two to four parallel explorers and then one explainer, in a fixed output shape (Overview, Key Concepts, How It Works, Where Things Live, Gotchas). Picket's research lane is one analyst writing a report in two passes, and `explaining` walks one scenario with worked data. `PS:skills/how/SKILL.md`, `core/skills/researching/SKILL.md:27-33`.
- **R-020** [VERIFIED] `why` finds motivation from history. It builds a code anchor (blame, pickaxe, PR numbers), lists the MCPs the session has, maps each to one of seven evidence categories (source control, tracker, documents, chat, observability, error tracking, analytics warehouse), spawns one investigator per category with a per-source playbook, then a synthesizer. Picket's analyst has `WebFetch`, `WebSearch` and Atlassian tools and no history or MCP-discovery procedure. `PS:skills/why/SKILL.md:33-60`, `PS:skills/why/references/source-playbook.md`, `core/agents/analyst.md:9`.
- **R-021** [VERIFIED] `why` grades every claim in five tiers (Direct, Supported, Inferred, Speculative, Unknown) with phrasing rules (no "because" without a citation), forbids citing code as evidence for its own intent, requires a "What We Don't Know" section naming the queries run, and warns that a user's embedded hypothesis is a candidate, not a conclusion. Picket has three markers and `[UNKNOWN]`. `PS:skills/why/references/epistemics.md:6-72`, `core/skills/documenting/SKILL.md:41`.
- **R-022** [VERIFIED] `teach` runs `how` and `why` and weaves one plain account built up diagram by diagram (draw A to B, redraw with C added), forbids stock framing labels, and offers "convince me it fixes the cause" as a framing. `recall` fans out across the user's own chat history and the shared record and returns a capsule, thread tags (`[merged #N]`, `[open PR #N]`) and one next move. Picket's `resuming` reads state on disk and says not to read the transcript; nothing rebuilds context about a topic across sessions. `PS:skills/teach/SKILL.md:12-18`, `PS:skills/recall/SKILL.md:24-34`, `core/skills/resuming/SKILL.md:24`.
- **R-023** [VERIFIED] `ketchup` is a catch-up format for an async user: under 150 words, plain words, one sentence stating how many things need the user, summary lines that stay true alone, then action items each with a recommendation and what happens on silence, plus size-limited visuals. Picket's gate packet is a fixed two-line shape rendered by code from the developer's block. `PS:skills/ketchup/SKILL.md:15-30`, `core/skills/ordering/steps/30-gate.md:1-22`.
- **R-024** [VERIFIED] Both avoid asking when the code can answer. pstack goes further: before any "which approach" question the lead must classify it, and a fact that "you could observe by running something" is "not the human's to answer", so it is prototyped. Picket's `understanding` interview prefers Grep and Read to questions and records `OQ-###` with a fallback. `PS:skills/poteto-mode/SKILL.md:20`, `core/skills/understanding/steps/02-interview.md:7`, `core/agents/architect.md:37`.

### Design and parallel exploration
- **R-025** [VERIFIED] `architect` writes the caller's usage first, derives types and signatures from it, and runs `arena` to get at least two "structurally distinct" candidates ("Design it twice") before synthesis; a scrap rule (Phase E) throws a sketch out when the same workaround, an `any`, or a lock reflex recurs. Picket's architect agent writes one recommended design with `Instead of:` per decision and no parallel candidates. `PS:skills/architect/SKILL.md:27-40,55`, `core/agents/architect.md:31`.
- **R-026** [VERIFIED] `design-red-flags.md` lists eight shapes to reject, written for "an agent that sees only the files it opened and copies the nearest example": shallow module, information leakage, temporal decomposition, pass-through method, split ownership, two ways to do one task, importable internals, hand-synced list. Picket's reviewer has clean-architecture and vertical-slice concern files, and its architect is told to prefer "boring patterns". `PS:skills/architect/references/design-red-flags.md`, `core/skills/reviewing/steps/50-concern-clean-architecture.md`.
- **R-027** [VERIFIED] `arena` runs six phases (frame with a rubric, fan out in separate worktrees, cross-judge, pick a base, graft by hand, verify) and `swarm` partitions slices or races with a declared selection rule; a swarm worker's result without the SHAs and method its brief names is dropped and respawned once, and a gap is not a pass. Picket's only parallelism is the design lane starting the developer and the cross-check reviewer together. Agent-skills' `/ship` fan-out is the closest shared idea. `PS:skills/arena/SKILL.md:11-45`, `PS:skills/swarm/SKILL.md:36-40`, `core/skills/designing/steps/20-crosscheck.md:3`.
- **R-028** [VERIFIED] The Feature playbook writes a "throughput checkpoint" of four todo items (blocking first steps, independent workstreams, shared mutable state, smallest safe decomposition), delegates code to a subagent as a mandatory step "for review separation", and keeps code-coupled work with one owner. Picket's fast lane edits in the main session and its order lane runs one developer. `PS:skills/poteto-mode/playbooks/feature.md:7-12`, `core/skills/expediting/SKILL.md:32-38`.
- **R-029** [VERIFIED] `figure-it-out` designs a bespoke playbook when none fits: falsifiable done predicate, rigor scaled to blast radius, verification harness built first from the pre-change state, verdicts VERIFIED, NOT VERIFIED or INCONCLUSIVE (inconclusive is not a pass). Picket's equivalent for an unfitting request is lane escalation or `consulting`. `PS:skills/figure-it-out/SKILL.md:14-46`, `core/skills/expediting/SKILL.md:43-46`.

### Build and verification
- **R-030** [VERIFIED] The Bug fix playbook: reproduce yourself on the matching surface (asking the user only with a stated reason), binary-search the cause with runtime evidence, "belt-and-suspenders that might help is a hypothesis, not a fix", revert what a refuted hypothesis motivated, stage commits so the failing repro lands before the fix, and paste failing-then-passing output verbatim. Picket has no bug path; a fix is a fast-lane change checked after the edit by `picket check` and `picket drive`. `PS:skills/poteto-mode/playbooks/bug-fix.md:5-14`, `core/skills/expediting/steps/30-check.md:6-14`. Agent-skills' debugging skill is the shared idea.
- **R-031** [VERIFIED] `tdd` applies only when a failing test is cheap: write the smallest focused test, run it to see it fail for the intended reason, fix, rerun; "prefer no new test over a bad test" (one that mostly tests mocks or encodes internals); never weaken assertions to match a wrong implementation; report the failing-before evidence. `principle-test-behavior-not-implementation` adds a two-edit check (break the behavior, then change the internals). `PS:skills/tdd/SKILL.md:26`, `PS:skills/principle-test-behavior-not-implementation/SKILL.md:13-15`. Picket's developer writes unit tests only and the reviewer row Ts4 flags a test that only asserts a mock call. `core/agents/developer.md:29`, `core/skills/reviewing/steps/10-alignment.md:58`.
- **R-032** [VERIFIED] The Refactoring playbook pins behavior first with a characterization test, snapshot or equivalence harness ("type check and lint are not a pin"), requires an old-versus-new equivalence check for larger reshapes, and judges success by reduced reader load, reverting if there is none. A grep of `core/` for "characterization" and "equivalence" finds nothing. `PS:skills/poteto-mode/playbooks/refactoring.md:7-18`. Shared with agent-skills' brownfield guidance.
- **R-033** [VERIFIED] Number discipline: `benchmark-checklist` (seven questions: why not double, was it tuned, did it break limits, did it error, does it reproduce over alternating runs, does it matter end to end, did the work happen), `explain-the-number`, the Perf playbook's seven "mantras" ordered cheapest first, and Hillclimb (frozen harness, `decision.tsv` row per attempt, one commit per accepted win, a stop predicate pairing a target with an attempt floor). Picket applies this discipline to itself in `bench/` and gives the developer no such skill. `PS:skills/benchmark-checklist/SKILL.md:21-35`, `PS:skills/poteto-mode/playbooks/hillclimb.md:7-24`, `bench/README.md:35-49`. Agent-skills' performance skill is the shared idea.
- **R-034** [VERIFIED] Forensics playbooks return a diagnosis, not a fix. Runtime forensics instruments the live process; Trace forensics loads a captured cpuprofile, heap snapshot or spindump into sqlite ("one row per sample, frame, or node") before reading it, maps the hot frame to source, and marks a finding without a paired capture as the strongest hypothesis, not a confirmed cause. `PS:skills/poteto-mode/playbooks/trace-forensics.md:7-13`, `PS:skills/poteto-mode/playbooks/runtime-forensics.md:7-12`.
- **R-035** [VERIFIED] Visual parity is baseline-first: a screenshot harness before any migration, named anti-shortcut clauses (no harness edits, no baseline tampering, no restructuring to pass a diff), one component at a time in separate worktrees, a nonzero image diff is a fail. Picket's `drive` records HTTP hits or a CLI run and has no image comparison. `PS:skills/poteto-mode/playbooks/visual-parity.md:7-14`, `core/lib/drive.mjs`.
- **R-036** [VERIFIED] `create-verification-skill` generates a project-local `verify-<app>` skill with Launch (ready means usable), Doctor, Drive, Evidence, Cleanup and Helpers sections plus a feature map (one file per user-facing feature with four fixed H2s), and must run its own output once before handing it over. `maintain-verification-skill` audits it with one read-only source reader per feature and one live pass, ending `clean`, `changed` (one pull request) or `blocked`. The driver itself (`control-ui`, `control-cli`) ships in another plugin. Picket's `picket drive` is a generic command and keeps no per-app map. `PS:skills/create-verification-skill/SKILL.md:28-38`, `PS:skills/maintain-verification-skill/SKILL.md:11-30`, `PS:README.md:253-261`, `core/skills/expediting/steps/30-check.md:14-20`. Agent-skills' browser testing is the shared idea.
- **R-037** [VERIFIED] 24 one-rule principle skills are indexed inline in `poteto-mode`. The router must name each principle that shaped a decision and the choice it changed, and cite only principles whose leaf file it read this session. Several carry a self-check, for example Build the Lever: "if you cited it and there is no codemod, script, generator, or delegate skill in the diff, you didn't apply it". Picket has no principle layer; its standing rules are four injected files and reviewer rows. `PS:skills/poteto-mode/SKILL.md:15`, `PS:skills/principle-build-the-lever/SKILL.md:18`, `core/rules/`.
- **R-038** [VERIFIED] pstack's reply rules apply to every answer: every claim carries "its evidence or its label in the same sentence" (measured, inferred, guess), impact is framed for the consumer then the maintainer, and a link or citation is never made up. Picket uses VERIFIED, INFERRED and ASSUMED markers only in reports and `explaining`; the developer block has a `Verified:` line. `PS:skills/poteto-mode/SKILL.md:105-113`, `core/skills/documenting/SKILL.md:41`, `core/agents/developer.md:56`.
- **R-039** [VERIFIED] Learning loops that change the repository or skills. `correct` groups repeated mistakes into classes (a class counts after two occurrences), fixes each at the highest level that works (architecture, then types, then a lint whose error names the fix, then a test, docs last), proves each new check fails on a real past mistake, and keeps a table pairing each rule with what enforces it. `reflect` runs three reviewers and a synthesizer, filters by durability, specificity and "skill-was-used", and applies nothing without approval. `automate-me` mines transcripts into a personal `-mode` skill. Picket's learning loop is the bench plus `memory: project` on its agents. `PS:skills/correct/SKILL.md:17-31`, `PS:skills/reflect/SKILL.md:41-48`, `PS:skills/reflect/references/synthesizer.md:21`, `core/agents/analyst.md:13`.

### Review, comments and quality content

## Glossary
- **Playbook**: a step list inside pstack's `poteto-mode` that the model copies into its todo list; it is a file, not a skill, and has no slash command.
- **Principle skill**: a one-rule pstack skill (for example `principle-prove-it-works`) that other skills cite by name.
- **Frontier**: in babysit, shipping and orchestrate, the lowest unmerged pull request of a stack.
- **Standing orders**: orchestrate's numbered constraint file, pasted verbatim into every spawn so directives do not decay.
- **Feature map**: a verification skill's directory of one file per user-facing feature, each saying how to reach it, how to drive it and what end state proves it.
- **Patch-id**: the hash `git patch-id` gives a diff; shipping compares it before and after a rebase to decide whether an old verdict still applies.
- **Code judo**: pstack's term for a restructuring that deletes whole branches or layers while keeping behavior.
