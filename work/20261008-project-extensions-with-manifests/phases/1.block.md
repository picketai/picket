Decisions: **the schema-1 contract your gate confirms.** Four points, all additive; each is a list of files or records inside the extension folder.
1. `rules`: Markdown files whose text goes to the lead and every agent.
2. `agents`: Markdown files for one role only, keyed by `lead`, `analyst`, `architect`, `developer` or `reviewer`.
3. `review_steps`: checklist files, each `{ path, min_size: small|medium|large }`, which the reviewer loads from that review size up.
4. `preflight`: declarative checks `{ id, kind: path_exists|env_set|command_on_path, value, level: warn|fail, message }`, none of which runs a command.

Besides the points, a manifest holds `name` (it must equal its folder and match `^[a-z0-9][a-z0-9-]{0,39}$`), `version` (SemVer), `schema` (an integer) and an optional `description`. **Refusal:** an extension is refused, with one reason, and then adds nothing anywhere, when any of these holds:
- the manifest has a top-level key outside those eight;
- its `name` differs from its folder;
- its `version` is not SemVer;
- its `schema` is not in `SUPPORTED_SCHEMAS = [1]` ("schema N is not supported by this Tether (supports 1)");
- a listed path is absolute, leaves the folder by `..` or by a symlink or junction, or is missing;
- a text file holds a line that is exactly a verdict token;
- it is listed with no folder or no manifest, or listed twice.

A folder that is not listed is only reported as unlisted. **Irreversible:** shipping extension.schema.json with schema 1 fixes these four points and their fields; any later change to them needs schema 2.
