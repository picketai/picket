lane: design. Build Tether extensions: a project customizes Tether through `.tether/extensions/<name>/extension.json` folders, enabled and ordered in `.tether/config.json`, project-local only in the alpha. An extension adds content at named extension points (agent additions, review steps, preflight checks) and never replaces or removes core behaviour; the floor (verdict tokens, `tether route` as the only state mutator, the guards, the user gate, the budgets) stays out of its reach. The manifest carries identity, version and a `schema` number that versions the set of extension points, and the kernel refuses an extension whose schema it does not support. Rules already reach the lead and every teammate by hook injection with extension additions after core (SDR 00001). A project's own small additions are an extension too. Decisions on record: `.claude/MEMORY.md` (glossary: Extension, Extension point, Floor; Decisions list) and `artifacts/strategy/decisions/00001-tether-ships-claude-code-plugin.md`.
