Fix `picket env` on a real container engine. With Podman 5.7.0 and docker-compose 2.40.3 installed, `picket env check --root test/fixtures/env/umbrella` exits 2 with "refused: compose config --format json --profile picket-data failed", and `node scripts/test.mjs env` fails both real-engine tests (test/env/model.engine.mjs T-2.7 and test/env/lifecycle.engine.mjs T-10.1 to T-10.3) on that same first call. Root cause, reproduced by hand: `--profile` is a global Compose flag and must come before the subcommand; `compose config --format json --profile picket-data` answers "unknown flag: --profile", while `compose --profile picket-data config --format json` prints the model. The fake engine accepted the wrong order, so no test caught it. Fix the argument order in the engine adapter wherever a profile is passed, make the fake engine refuse a global flag placed after the subcommand, keep the real cause ("unknown flag: --profile") in the refusal text instead of only the wrapper's last line, and then run `node scripts/test.mjs env` on this machine until the real-engine tests pass, fixing whatever further faults the real engine shows in the env lifecycle (check, trial, start, stop, purge).
