## Phase 3 of 20261114-env-verbs-pass-on-real-engine: The lifecycle passes on Podman

The env lifecycle now passes on Podman 5.7.0 with Compose 2.40.3: check, trial, start, stop and purge all succeed and leave nothing behind. That took one Picket fix, which is staged.

The run found one Picket fault. The call is `compose port <service> <target>`. Podman 5.7.0 prints the published port with an empty host (`:33745`), so `env start` built `http://:44011`, and the lifecycle test's `fetch` failed with `Invalid URL`. `src/lib/verbs/env/start.mts` now treats an empty host as "any address" and reaches the port on `127.0.0.1`. The fake engine now answers `compose port` with `:49153`, the shape Podman prints, and `test/env/fake-engine.test.mjs` pins that answer. A new unit test in `start.test.mts` covers the same case.

`env stop` was blocked last turn because the system's security policy (AppArmor) would not let Podman stop the pasta network process. That host setting is now fixed: `/etc/apparmor.d/usr.bin.pasta` line 20 allows Podman's stop signal, and the kernel log shows no new denials. Before the run I removed the network and volume the earlier failed runs had left.
