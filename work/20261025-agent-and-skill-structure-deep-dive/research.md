# Report: Agent and skill structure deep dive

## Summary
The four agent shells are small (52 to 69 lines against a cap of 120) and share Entry, Constraints and Output sections that close on a verdict token, yet the tests read check only their line count, their skill references and a docs section per agent, so an agent shape test does not exist [INFERRED]. The skill side is better covered (step and checklist names, "Use when" descriptions, routing cases, manifest, reach), but nothing checks SKILL.md sections or frontmatter keys, and several verified contradictions and stale cross references sit in skill and agent text (R-035 to R-042) [VERIFIED]. F-1 has two measured bounds on Claude Code 2.1.310: strict validation fails a frontmatter-less file under `agents/` while a plugin-root folder passes, and a hook injects at most 10,000 characters, which the reviewer's always-loaded checklists (10.3 KB) already exceed [VERIFIED]. Claude Code now offers agent and skill fields the repo does not use (`disallowedTools`, `maxTurns`, `omitClaudeMd`, `when_to_use`, `paths`, `allowed-tools`, `disable-model-invocation`), and plugin agents ignore `hooks`, `mcpServers` and `permissionMode` [VERIFIED]. Anthropic's Opus 5 and 5.5 guides say older prompts run unchanged but advise dropping prompt-level verification, shaping narration with positive examples and not filtering inside a review prompt, and several Picket instructions sit in those classes [INFERRED].

## Context
Asked: an agent file structure and its test, a skill file structure and its test, the agents and skills folder layout (F-1), what to improve in each of 4 agents and 17 skills, and what Opus 5.5 and recent Claude Code releases change. This deep pass read 61 Markdown files of the 91 under `src/skills/` (one over the cap of 60, because the three documenting templates came with the outline), all four agents, the rules, the hook list, the build script and the tests named above, then the docs and guides listed in the frontmatter. Not read: 30 skill files (five documenting templates, `documenting/examples/api.md`, the documenting and reviewing scripts, fonts and `reference.docx`, two explaining examples, 6 ticketing templates and 6 examples, one branching manifest example); `docs/reference/` pages; the 58 KB audit of 2026-08-06 beyond its headings; changelog entries 2.1.282 to 2.1.298; hooks docs past character 200000; bench code. The Opus guides are titled "Opus 5" and "Opus 5.5"; the user's "Opus 4.8 to 5.5" maps to both.

## Structure
Agents: `src/agents/{analyst,architect,developer,reviewer}.md`, each frontmatter plus identity, `## Entry`, `## Constraints`, an output block. Skills: 17 folders with `SKILL.md`, 40 step-like files (`steps/`, `checklists/`, `shared/procedures/`), the longest 63 lines against a cap of 80. Rules: 5 files injected by `inject.rules` on SessionStart and SubagentStart. Build: `scripts/build.mjs` copies every non-code file from `src/` to `dist/` unchanged (`isCopied`), writes `hooks.json` from `src/lib/hooks.mts`, and bundles hooks. The lead pastes six agent sections from skill files into spawn messages (R-047). The only cross-owner shared folder is the document kit, `documenting/templates/` and `documenting/scripts/` (R-045).

## Dependencies and relationships
Build copies instructions unchanged; any inlining would be a new build step (`scripts/build.mjs:130-132,238`). Hooks load from `dist/hooks/hooks.json`; `inject.rules` reads `dist/rules`, and `inject.extensions` adds per-role text from `.picket/extensions/` within 10,000 characters. The kernel parses agent block labels and finding lines by position (`block-format-couplings.md`). `docs/reference/agents.md` and `skills.md` need one section per agent and skill (`test/repo/docs.test.mjs:141`). Tests mirror a manifest of 17 skills and 8 hook events (`plugin-layout.test.mjs:82-84,116`). Agent memory folders are tracked per agent name. The plugin ships `bin/` launchers; Claude Code puts a plugin's `bin/` on the shell `PATH`.
