## Phase 5 of 20261119-database-guards-and-confirmed-sql-runs: Fix the cumulative review's connection-reader finding

I fixed the major finding as D-002 (r2) amended it: `readTarget` now refuses a connection string that names another server outside the keys it reads. The fix and its tests are staged as 3 files.

What changed:
- **Server keys:** `network address`, `failover partner` and `failover_partner` now count as server keys. A `Failover Partner` next to `Server` is a repeated server, so it is refused.
- **URL query:** a URL with any query is refused, with the problem `it carries a URL query, which a driver can read as another server or database`.
- **URL path:** a URL path with more than one segment is refused with `its URL path holds more than the database`. A trailing slash after the database is still accepted.

Red: connection.test.mts "an ambiguous, incomplete or unknown form is a problem with no target, and never quotes the string (T-1.2)". I did not re-run it on the code before the fix. Its new strings are the reviewer's probes, which that code read as `{ target: { server: "sql01", database: "orders_test" } }`.
Root cause: `urlTarget` read only `url.host` and the first path segment and ignored the query. `SERVER_KEYS` left out `failover partner` and `network address`, so a second server under those keys was never counted.
