## Phase 3 of 20261119-database-guards-and-confirmed-sql-runs: The marked run asks through the escalation route

Phase 3 is done and staged as 22 files. When the lead runs a plain `picket data run`, guard.bash now denies it and names the marked form. The marked form plans the run first, and a plan refusal denies it in every mode. In an asking mode, the guard snapshots the shown bytes, writes a confirmation row that holds only the nonce's hash, and asks with `updatedInput` carrying `--confirmation <nonce>`. Each later Bash or PowerShell command of the same session voids that session's pending rows.

What changed:
- **Confirmed subverbs:** `run` under `data` carries `confirmed: true`. `kernelClass` returns `deny` for it. `isConfirmedCall` finds the call past assignments, the `--human`/`--json`/`--pretty`/`--root` global flags and the `node …/picket.mjs` launcher. `CONFIRMED_SUBVERBS` is the table the closures read.
- **Plain-form denial (`judge.mts`):** the reason is the designed text, `PICKET_ESCALATE="<why>" picket data run <id> <entry>`.
- **Marked form (`escalation.mts`):** a new `judgeDataRun` checks in this order: shape, then `planRun` (`why: "data_plan"`), then the route's existing checks for mode, saved rule and refused-before, then `confirmRun`, then `ask`. Every data-run denial ends with the designed text in place of `! <command>`. Existing escalations behave as before: `escalationVerdict` was split into `dialogInput` and `dialogVerdict` so both paths share them.
- **Confirmation rows (`confirm.mts`):** holds `Confirmation`, `confirmRun` (writes the snapshot through a temporary name and rename, then appends the row) and `voidPending`.
- **`commandKey`:** drops a trailing `--confirmation <64 hex>`.
- **Hook output:** `ask` takes an optional `updatedInput`, and `guardBash` voids the session's pending rows before it judges the command.

Decisions:
- The PowerShell plain-form denial names `$env:PICKET_ESCALATE = "<why>"; picket data run <id> <entry>` in place of the Bash spelling, so a PowerShell user gets a form that works.
- `isConfirmedCall` reads the verb past global flags and the node launcher. `picket --root . data run …` would otherwise class as a plain kernel call, which the `Bash(picket *)` allow rule passes without a dialog.
- When `voidPending` throws, guard.bash denies the command with the cause. This fails closed: if the void were skipped, a refused dialog's nonce would stay usable.
- `confirmRun` itself checks that the bytes match the planned digest, so a test can pin it. A mismatch denies with `why: "data_plan"`.
- The `--confirmation` flag in the rewritten command is quoted word by word. In PowerShell, a quoted launcher gets `& ` in front.
- `rules.mts` is outside the touch set, so the ask that carries `updatedInput` is typed `RewrittenAsk` in escalation.mts, and `updatedInputOf` reads it.
