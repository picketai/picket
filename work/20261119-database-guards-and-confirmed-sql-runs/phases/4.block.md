## Phase 4 of 20261119-database-guards-and-confirmed-sql-runs: The verb runs a confirmed snapshot once

`picket data run` now runs only with a confirmation from the dialog, and only once. Phase 4 is done and staged as 7 files. The verb first takes the confirmation that the hook wrote. Then it plans the run at the confirmed digest, checks the snapshot's bytes, and compares its own reading of the connection with the confirmed pair. Only then does it call compose, with the snapshot mounted at `/picket/run.sql`.

What changed:
- **Taking a confirmation (`takeConfirmation`):** it picks the newest row for the session, item and entry whose nonce hash matches, compared with `timingSafeEqual`. It refuses when:
  - there is no such row, or the session or nonce is missing (the reason names the marked form and the asking modes);
  - the row was voided or already taken (the reason names which);
  - the row is older than `CONFIRMATION_WINDOW_MS`.

  Otherwise it appends `{ id, taken_at }` and returns the row.
- **Planning at the confirmed digest:** `planRun` takes an optional `{ sha256 }`. With it, the approval is checked at that digest and the live file is not hashed.
- **Run rows:** each row carries `confirmation` and `approved_at`. Rows written before this change still read.
- **`--confirmation` flag:** `parseRun` reads an optional value of 64 lowercase hex characters, and refuses any other value with a usage error. `USAGE` is unchanged.

Decisions:
- The refusals for a null session or a missing nonce live in `takeConfirmation` rather than in `runSqlEntry`, so one place owns every "no confirmation" reason and its unit test covers all of them.
- `DataRun` keeps the two new fields optional so that old rows still read, including in `close.mts`, which is outside the touch set. The verb writes them through the new type `ConfirmedDataRun`, which requires both fields.
- At a confirmed digest, `planRun` still calls `sqlFile`, so the entry's path is still checked as a file under `.picket/env/data/`. A deleted file therefore still refuses; an edited file does not.
- The existing run tests now make a real confirmation row through a `confirm` helper. The mount they assert is the snapshot path, not the live file.
