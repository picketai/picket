## Phase 2 of 20261009-bench-stops-servers-its-runs-started: The job wrapper and the run's record

On Windows, each `claude` call now runs inside a job object. At the end of the run the sweep stops every live process the run started, listening or not, and leaves processes started outside the run alone. The record gains `orphans` (processes stopped) and `tracked` (job members seen).

Decisions: **a finding that changes the mechanism:** a job the wrapper puts itself in does not catch its children on this machine (a direct `node` child was outside the job), most likely because the wrapper's own outer job allows silent breakaway. So the wrapper starts the command and immediately calls `AssignProcessToJobObject` on it, the same step the order's probe used; the command's children then join the job. That leaves a window of a few milliseconds before the assign, harmless for `claude`, whose startup is far slower than that. In the drive, 38932 (Git Bash's launcher stub) exited once its `node` child was stopped, so `orphans` counts only what this sweep stopped (1), while the test checks that every picked pid is gone. The wrapper parses its own arguments, because a pwsh `param` block bound `--` and `-lc` as parameter names. The old `listenerPids` and `killListeners` and the stale port-hygiene comments in ports.mjs and run.mjs are deleted. The log line names each stopped pid with the ports it listened on.
