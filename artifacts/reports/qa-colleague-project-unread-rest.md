# Report: QA colleague project, the unread rest

## Summary
His project answers two of the three unknowns, and the answers are about process more than code: in the files read no step retires a case and none edits one by hand, because scripts replace a story's cases and edit case text by substitution (R-019) [INFERRED]. ## Structure
The case pipeline is a chain of skill and script steps: `generate-testcases` writes batch files, `merge-sprint-cases.py` merges and validates them into `generated-testcases.json` and per-module `story-testcases.json`, `acquire-data` queries the database, `enrich-sprint-cases.py` writes real values into the steps, `upload-enriched-to-ado` pushes them into a new ADO suite, and `automate-testcase-poc` marks one case as automated (R-017, R-018, R-037). Drift checks sit beside it: contract (`drift-diff.js`, `drift-apply-patch.js`) and data (`detect-data-drift`). Checks of the environment are `deploy-check.js`, `vpn-state.js` and the readiness skill (R-004, R-025, R-031). Run files in `qa/runs/` end in a verdict. Defects are `findings/FND-xxxx.md` with a generated index.

## Findings
Part 1: what serves the minimal verification
- **R-001** [VERIFIED] Contract change tiers. STOP (a path, required field, enum value or status removed, auth changed): tests are left alone and fail on purpose, "that is the alarm". PROPOSE (rename, new required field, stricter nullability): a patch file is written, not applied. AUTO-PATCH (enum added, field made nullable, status code added): a descriptor with a unique verbatim `find` string is applied on a `drift/auto-<date>` branch, only the affected specs run, and all edits revert on a failure. Never merged automatically; the baseline refresh is human only. `.claude/commands/(E) detect-contract-drift.md:22-58,106-117,155-163`. Partial answer to the draft's supersede rule (draft 1.8).
- **R-002** [VERIFIED] The nearest thing to regression targeting: for each contract difference the skill runs `grep -l` over `tests/**/*.spec.js` for the changed endpoint or field and records `verifySpecs`, "the minimal set of specs to re-run, never the whole suite". It starts from a spec diff, not a code change, and the model does the grep. `(E) detect-contract-drift.md:66,110`. No script computes it (R-026). Bears on draft hole 3.
- **R-003** [VERIFIED] A network failure is "inconclusive", not "no drift": the run exits 0 with a loud message and an empty diff is never read as a pass. `(E) detect-contract-drift.md:162`. Same rule as "does not start is not fails" (draft 3.5).
- **R-004** [VERIFIED] The readiness skill gives a verdict READY TO TEST, PARTIALLY READY or NOT READY. ## Glossary
- **Tier (STOP, PROPOSE, AUTO-PATCH)**: his three classes of contract change and what may be done to tests for each.
- **Lifecycle volatile**: a fixture that the write tests change on purpose, so a drift check must not reset it.
- **Ratchet**: an expected failure tied to a defect id; it turns red when the defect is fixed.
- **Descriptor**: a JSON file listing exact find and replace edits and the specs to re-run, consumed by the patch script.
