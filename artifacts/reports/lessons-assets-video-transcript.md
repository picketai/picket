# Report: Lessons from the assets video transcript

## Summary
The transcript is a 1 hour 4 minute talk by Lance, who says he is a member of technical staff at Anthropic, on five themes: audit prompts, use the prompt cache, design climbable evals, hill climb without overfitting, and build harnesses for long running agents [VERIFIED]. Picket already matches the talk on secrets, append only state, a code graded bench and a stable cache prefix, with a baseline cache hit ratio of 82 to 96 percent [VERIFIED]. The 37 skill files read in full hold none of the prompt rituals the talk names and no rule pair that demands opposite actions, only prose self check lists and one mild style tension, so the prompt audit theme gives little to fix [INFERRED]. The main gap is that `--check` does not gate cache hit ratio (R-022) [VERIFIED]. Next are untested agent effort levels (R-015) and no tuning and held out split of the 18 bench tasks (R-016), both needing an architect's call [INFERRED].

## Findings
- **R-001** [VERIFIED] The talk has five themes: audit prompts, use the prompt cache, design evals Claude can climb, hill climb without overfitting, harnesses for days long agents. `assets/youtube-transcriptassets.md:33`, `:128`, `:202`, `:272`, `:443`.
- **R-002** [VERIFIED] Prompt debt: "think step by step", verification rituals, double check, "be maximally thorough", scratch pads, and contradictory rules cost tokens and can lower quality on frontier models. His cure is the bundled skills `prompt audit` and `claude api prompt audit`; he says the cut-off model is "maybe Opus 4.5". `assets/youtube-transcriptassets.md:36-81`, `:1186-1201`.
- **R-003** [VERIFIED] His prompt audit example is a synthetic 50 ticket benchmark migrating Opus 4.8 to 5.5, anti patterns injected one by one. The transcript gives the direction (cost and quality both improve) and no absolute numbers. `assets/youtube-transcriptassets.md:88-125`.
- **R-004** [VERIFIED] The cache is a strict prefix match; any byte change in the prefix invalidates it. Order: system and tools, then project memory, then session state, then messages. Hit rate should be tracked. He reports up to 72 percent cost cut on internal benchmarks from cache fixes alone. `assets/youtube-transcriptassets.md:129-200`.
- **R-005** [VERIFIED] An eval is climbable when score rises with model size and with thinking, there is headroom at the frontier, run variance is low, and tasks are not ambiguous. `assets/youtube-transcriptassets.md:223-251`.
- **R-006** [VERIFIED] Hill climbing splits train and test, shows the climber only train failures, and reads "train up, test flat" as overfitting. Prompts and skills are the easiest surface and the easiest to overfit. The climber may not converge; when stuck it clusters failures and checks for ambiguous cases. `assets/youtube-transcriptassets.md:320-347`, `:635-700`, `:873-900`.
- **R-007** [VERIFIED] Cost search: a stronger model at low effort is often cheaper than a weaker model at high effort. He advises "low not medium" for Opus 5 to start, then dial up; effort is not a hard cap. One run cut cost 90 percent with better performance. `assets/youtube-transcriptassets.md:388-440`, `:934-967`, `:1216-1240`.
- **R-008** [VERIFIED] Grading: prefer deterministic checks; otherwise a rubric a human can apply, binary classes not 0 to 10 scales, agreement across models, replicates, pairwise comparison, a cheap model as judge. Do not build an eval only from one model's failures. `assets/youtube-transcriptassets.md:719-820`.
- **R-009** [VERIFIED] Reliability: harness (brain) and sandbox (hands) are separate; an append only session log lives outside both; secrets sit in a vault the model can reference but not read; context lives in an object the model can query so compaction loses nothing. `assets/youtube-transcriptassets.md:480-525`, `:1364-1403`.

## Glossary
- **Hill climbing**: letting a model change a prompt or skill again and again, keeping changes that raise an eval score.
- **Prompt cache**: reuse of an unchanged prompt prefix at a lower price; any change in the prefix voids it.
- **pass^k**: the share of tasks that pass on all k runs, a measure of repeatability.
- **Overfitting (eval)**: gains on the tuning cases that do not carry to real use.
