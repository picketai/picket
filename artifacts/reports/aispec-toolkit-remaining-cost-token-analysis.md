## Executive Summary

The AISpec toolkit is a five-agent development pipeline for Claude Code that tries to make multi-agent work cheap and repeatable through exact routing tokens, lazy-loaded instructions, mechanical scripts, and enforcement hooks. It matters because every ambiguity in those contracts either burns tokens on a wrong path or lets two components silently disagree about the same rule. The single most important finding is a live routing contradiction: on a failed cross-check, CLAUDE.md sends the architect into Amendment mode while the architect's own Design instructions say to re-enter Design mode — two paths that produce different artifacts. A gap-round re-read added two more live conflicts of the same class: CLAUDE.md and implement.md define incompatible mid-plan checkpoint rules (R-062), and a user-level `jira-items` skill collides verbatim with the ticketing skill's triggers, making Jira routing nondeterministic per session (R-072). A second gap round swept the residue the critic flagged: the analyst shell — the only agent outside the mode-file sweep — reconciles cleanly against the registries; the hooks layer has six scripts, not the five this report itself claimed twice (R-088); the architect-A9b → verify-assumptions handoff has no producer-side format contract (R-092); and `.claude/MEMORY.md` carries an unmitigated lost-update window (R-104, R-105). The reader should resolve the architect-flagged contract conflicts first, then close the silent-degradation holes listed in the recommendations.

## Background and Context

The toolkit lives in this repository's `.claude/` tree: agent shell files and shared YAML registries under `.claude/agents/`, enforcement hooks and telemetry under `.claude/hooks/` and `.claude/telemetry/`, fan-out workflow scripts under `.claude/workflows/`, and authoring/review/ticketing/session skills under `.claude/skills/`. CLAUDE.md is the team lead's routing contract binding all of it together.

It exists to convert a single-model coding assistant into a bounded-cost, low-variance delivery pipeline: analyst → consultant → architect → developer → reviewer, with user gates between phases. A prior audit (`artifacts/reports/agent-skill-audit-2026-05-26.md`) fixed most first-order gaps; this report reconciles seven fresh cluster readings — plus an eight-reading gap round (2026-07-16) that backfilled the lost eighth cluster (the `understanding` skill, R-051–R-055) and swept the cross-cluster seams the first pass left open, then a second six-reading gap round (same date, R-081–R-106) that closed the critic-flagged residue: the analyst shell, the hook count, the A9b seam, ticketing's pull direction, Cross-check's UNCLEAR grammar, and the consultant's MEMORY.md freshness controls — to catalogue what still leaks tokens, degrades silently, or lets two files state the same contract differently.

## Key Concepts

### Verdict token
An exact string (`APPROVED`, `CHANGES REQUIRED`, `ALIGNED`, `DRIFT DETECTED`, user `approved`) that gates a pipeline transition. Near-matches are rejections by design (tokens.yaml:11), so every consistency gap in token spelling or casing is a routing gap. Example: a user replying "LGTM" dispatches the developer's Rejection mode.

### Diff-size gate
The reviewing skill's token-economy cascade: Small diffs (≤3 files AND ≤50 LOC) load only the alignment and framework templates; Medium and Large load progressively more of patterns.md. It exists to keep small phases cheap, but what it skips is silently unreviewed (SKILL.md:68-76).

### Supersession ADR / effective-ADR chain
Amendments never edit an ADR in place; a new `NNNNM-<short-title>-r<N>` file carries only revised decisions, and readers must union the whole ancestor chain to reconstruct the effective ADR. Reviewer cost grows linearly with revision count (perphase.md:20-23).

### SELF_CHECKED carve-out
The architect may skip the reviewer cross-check only when all four triviality conditions hold; escalation is the default and self-certification the exception (CLAUDE.md:105-109). Several findings below concern who actually consumes this token.

### Plan-status stamping
`plan-status.mjs check|stamp` is the single mechanical authority on `**Status: Complete**` markers against `<!-- status:phase-N -->` anchors — both developer and reviewer are forbidden to eyeball stamps (developer.md:76; perphase.md:13).

## Glossary

- **Verdict token** — exact string gating a pipeline transition; near-matches are rejections by design (tokens.yaml:11).
- **Diff-size gate** — reviewing skill's Small/Medium/Large template-loading cascade keyed on changed files and LOC.
- **Supersession ADR** — `NNNNM-<short-title>-r<N>` amendment file carrying only revised decisions; ancestors are unioned into the effective ADR.
- **SELF_CHECKED carve-out** — architect's four-condition exception to the mandatory reviewer cross-check.
- **Stash dance** — `git stash --include-untracked && <test> && git stash pop`, the developer's sole mutating-bash exception for pre-existing-failure triage.
- **Fail-open / fail-closed** — whether a component's failure permits (guard.bash, verify-assumptions refuter) or blocks (cumulative-review refuter) the guarded action.
- **safe_dir** — branching's worktree directory name derived by replacing `/` and whitespace with `-`.
